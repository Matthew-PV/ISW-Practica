### FUNCIONALIDADES

Esta sección recoge las funcionalidades que piensa implementar la aplicación, sin querer ser una lista de requisitos que cumplirá la aplicación final. Estos están recogidos en otra sección del documento.

*# Ningún requisito entra en la disposición de la aplicación, o cómo la verá el usuario final.*



* Perfil de usuario: Conteniendo tu nombre de usuario, experiencias compartidas...

\# *¿Solo perfiles de personas, o también empresas?*



* Agregar amigos: Cada usuario podrá agregar amigos, o bien buscándolos por nombre de usuario, o bien sincronizándose con su libreta de contactos.



* Creación de "experiencias": A través de la aplicación, cada usuario tendrá la opción de diseñar lo que llamamos experiencias. Estas son colecciones de planes y actividades que hacen referencia a lugares específicos. Desde parques o museos, hasta restaurantes o negocios. Para diseñarla podrá configurar ciertas opciones, como añadir fotos o comentarios, incluir tarifas o mencionar eventos específicos.

*# ¿Dónde mencionamos que cada experiencia es por ciudad?*



* Compartir "experiencias": Cada usuario tendrá la opción de publicar sus experiencias, para que otros usuarios puedan acceder a ellas.

*# ¿Visibilidad? ¿Opción pública o solo amigos? ¿Dónde van a aparecer?*



* Búsqueda de "experiencias": Esta es la funcionalidad principal de la aplicación. Cada usuario podrá acceder a una sección en la que podrá explorar experiencias creadas por otros usuarios. También podrá buscar por nombre, tipo de experiencia, presupuesto, duración u otros criterios de búsqueda.



* ¿Guardar experiencias?: ¿Podrán guardarse algo que hayan visto y les haya gustado? ¿Podrán modificarlo?
* ¿Seguimiento de experiencias?: ¿Podrán iniciar una experiencia como si fuera una lista a seguir? ¿Checkboxes?
* ¿Chat? ¿Alguna más?
